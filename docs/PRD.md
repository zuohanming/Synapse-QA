## 1. 文档目的

本文档汇总 Synapse QA 当前已经实现的产品能力、业务规则、用户流程和系统边界，为后续需求评审、迭代开发、测试验收及交付部署提供统一依据。

本文档以当前仓库代码为事实来源。标记为“占位”或“待完善”的内容已有菜单入口或初步界面，但尚不能视为完整交付能力。

## 2. 产品概述

Synapse QA 是面向测试团队的自动化测试管理与执行平台，覆盖测试资产维护、可视化步骤编排、测试用例管理、分布式执行器管理、批量执行、实时日志、测试报告、通知和系统配置。

平台由三个运行端组成：

- 管理平台：React + Vite，提供测试资产、执行、报告和系统管理界面。
- 平台 API：Go + Gin + PostgreSQL，负责认证、数据管理、执行调度、状态归档和通知。
- 执行器：Python + FastAPI + Playwright，负责任务接收、并发执行、进度上报和结果回调。

## 3. 产品目标

- 集中管理界面自动化和接口自动化测试资产。
- 使用画布降低复杂 UI 自动化步骤的编排与调试成本。
- 将平台管理与实际任务执行解耦，支持独立执行器横向扩展。
- 支持少量用例即时执行和大量用例分批调度。
- 实时呈现执行步骤、日志、状态和最终报告。
- 通过项目、产品、模块、环境和全局变量建立可复用的测试上下文。

## 7. 功能需求

### 7.1 登录与认证

- 支持用户名、密码登录。
- 登录成功后保存平台访问 Token，并用于后续 API 请求。
- Token 无效或过期时清理登录状态并返回登录页。
- 登录页展示默认演示账号提示。
- 后端接口除健康检查、登录、注册和执行器回调外，默认要求 Bearer Token。

### 7.2 首页项目概览

- 展示平台主要资产和运行数据概览。
- 提供进入常用管理模块的入口。
- 数据来源于系统概览接口。

### 7.3 界面自动化

#### 7.3.1 页面元素

- 按项目/产品、模块和页面维护页面对象。
- 支持新增、编辑、删除和列表查询。
- 页面下可维护多级定位策略，包括定位类型、定位值和索引。
- 支持 AI 定位提示、等待时间等辅助配置。
- 页面与元素采用软删除，避免直接破坏历史引用。

#### 7.3.2 页面步骤与可视化画布

- 支持创建和维护可复用页面步骤。
- 通过画布添加、连接、选择、编辑和删除节点。
- 普通节点按连接顺序执行；条件节点必须同时配置真、假分支。
- 调试前校验节点是否已保存、流程是否完整、条件分支是否齐全。
- 调试过程实时轮询执行器任务状态并展示步骤进度与日志。

当前画布节点包括：

| 节点分类 | 主要能力 |
| --- | --- |
| 元素操作 | 打开页面、等待、点击、双击、输入、清空、悬停、截图等 |
| 断言操作 | 文本、标题、URL、元素存在性、可见性、启停状态、勾选状态、值、属性、数量、变量和正则断言 |
| SQL 操作 | 执行 PostgreSQL 查询并将结果写入变量 |
| 自定义变量 | 设置运行时变量，支持引用前序变量 |
| 条件判断 | 比较左右值并进入真或假分支 |
| Python 代码 | 在执行器进程中运行自定义 Python 代码；当前未提供沙箱隔离，不应执行不可信代码 |

变量引用统一使用 `${variable_name}` 语法。

#### 7.3.3 测试用例

- 支持按 ID、名称、项目/产品、模块、类型、优先级、状态和负责人筛选。
- 支持新增、编辑、详情、删除。
- 支持关联产品、模块、页面及多个页面步骤。
- 支持 UI、API、单元和混合类型。
- 支持 P0、P1、P2、P3 优先级。
- 支持测试前置条件、预期结果、标签、负责人等信息。
- 支持最多 200 条用例的单次导入，以及按筛选条件导出。
- 支持参数化数据集的新增、编辑、启停和删除。
- 支持单选或多选用例发起执行。
- 执行前弹窗选择有头或无头模式。
- 执行前校验是否存在在线且支持对应类型的执行器；无可用执行器时给出 Toast 提示。

#### 7.3.4 全局变量

- 支持文本、数字、布尔和 JSON 类型。
- 支持项目级和环境级作用域。
- 选择环境级作用域时，先选择项目/产品，再联动加载该产品下的环境。
- 变量名必须以字母或下划线开头，可包含字母、数字、点、横线和下划线。
- JSON 类型保存前校验格式。
- 支持启用、停用、搜索、编辑、删除及复制引用语法。
- 变量优先级规则：用例变量 > 环境变量 > 项目变量。

### 7.4 接口自动化

#### 7.4.1 接口管理

- 支持按 ID、接口名称、URL、项目/产品、模块、端类型、方法、协议和状态筛选。
- 支持新增、编辑、删除、详情和执行入口。
- 新增接口时项目/产品与模块联动。
- 支持 GET、POST、PUT、DELETE、PATCH 方法。
- 支持 HTTP、HTTPS 协议和 WEB、APP 端类型。
- 接口详情工作台支持维护：
  - 请求头；
  - 查询参数；
  - 请求体；
  - 后置 JSONPath 提取；
  - 后置正则提取；
  - 后置脚本；
  - 结构化断言配置。
- 支持直接调用接口并展示状态码、响应时间、执行状态、响应头、响应体和实际请求。

上述配置项当前可以保存和回显；浏览器调试调用实际应用请求头、查询参数和请求体，但后置提取、后置脚本及结构化断言尚未接入浏览器调试执行链路。

当前接口调试由浏览器页面直接发起请求，可能受到目标服务 CORS 策略限制；通过平台执行器代理调用属于后续增强项。“接口调试”特指详情工作台中的单次浏览器请求，不等同于正式批次执行。

#### 7.4.2 项目默认请求头

- 支持按项目新增、编辑、删除、启用和停用默认请求头。
- 请求头包含名称、默认值、说明和状态。
- 支持按项目及请求头名称筛选。
- 接口根据所属产品反查项目，并加载该项目启用的默认请求头。
- 执行接口时先加载项目默认请求头，再合并接口自定义请求头。
- 同名请求头冲突时接口自定义值优先。
- 接口自定义空值仍视为显式覆盖；项目或产品关联失效时不加载项目默认请求头。
- 当前重复名称主要由管理页面进行大小写不敏感校验，最终请求头名称规范化遵循浏览器 Fetch API 行为。
- 当前默认请求头值按明文保存和展示，`${变量名}` 尚不会在接口调试中自动替换。

#### 7.4.3 当前边界

- “接口自动化 / 测试用例”当前为菜单与空状态入口，未形成独立的接口用例编排闭环。
- “接口自动化 / 全局变量”当前为菜单与空状态入口，尚未独立于界面自动化全局变量实现。
- 接口批量执行按钮已有界面入口，完整批量执行链路仍待实现。

接口自动化能力矩阵：

| 能力 | 数据建模/配置 | 单次调试 | 批次执行与报告 |
| --- | --- | --- | --- |
| 接口定义 | 已实现 | 已实现，浏览器直接请求 | 未形成完整入口 |
| 请求头、参数、请求体 | 已实现 | 已应用 | 未形成完整入口 |
| 后置提取、脚本、断言 | 已实现保存与回显 | 尚未实际执行 | 未形成完整入口 |
| 接口用例 | 菜单占位 | 不适用 | 未实现 |
| API Runner | 执行器底层已具备 | 未接入详情工作台 | 尚未接通平台业务入口 |

### 7.5 测试配置

#### 7.5.1 项目配置

- 支持项目的分页查询、新增、编辑、启用、停用和删除。
- 项目名称唯一。

#### 7.5.2 项目产品与模块

- 产品必须归属于项目。
- 支持维护产品名称、UI 类型和 API 类型。
- 支持产品模块的新增、编辑、删除。
- 模块支持一级、二级分类信息。
- 产品和模块用于页面、步骤、用例、接口等资产的联动选择。

#### 7.5.3 测试对象

- 测试对象归属于产品。
- 支持维护环境名称、目标地址、部署环境、自动化类型、负责人及读写开关。
- 同一产品下环境名称唯一。
- 测试对象为环境级变量及执行上下文提供环境来源。

#### 7.5.4 执行器配置

- 以卡片形式展示执行器名称、ID、地址、状态、版本、能力、最近心跳和负载。
- 支持新增执行器并生成其专属 Token。
- Token 与执行器一一对应，重新生成后旧 Token 失效。
- 支持查看运行中任务数、排队任务数和最大并发数。
- 状态自动刷新，也支持手动刷新。
- 在线状态基于心跳判断：持续无心跳时依次进入可疑和离线状态。
- 最近心跳超过 30 秒标记为可疑，超过 60 秒标记为离线；恢复有效心跳后重新显示在线。

### 7.6 执行器

#### 7.6.1 登录与连接

- 桌面执行器首次打开显示 Token 登录页。
- 用户输入平台生成的执行器专属 Token 并点击连接。
- 验证成功后保存 Token 并进入执行器主界面。
- Token 无效或失效时退出主界面并返回登录页。
- 连接、启动、停止及鉴权异常向平台产生通知。

#### 7.6.2 服务与状态

- 支持在桌面界面启动和停止本地执行服务。
- 展示平台地址、本地地址、运行状态、健康状态、执行能力和运行日志。
- 启动后向平台注册，并按默认 10 秒间隔发送心跳。
- 心跳上报最大工作线程数、运行中任务数、排队任务数、支持类型和依赖自检结果。

#### 7.6.3 任务能力

- 支持 UI、API、脚本、Pytest 单元测试和空操作任务。
- UI 任务基于 Playwright，可选择有头或无头模式。
- 使用线程池按 `max_workers` 并发执行任务。
- 本地活动任务达到 `max_workers × 2` 时拒绝继续入队，避免队列无限增长。
- 执行过程中按步骤更新日志与进度。
- 完成、失败或取消后回调平台更新任务及批次状态。

执行器注册和心跳使用 `X-Executor-Token` 请求头。平台向执行器提交任务依赖已登记的执行器地址；任务完成回调以平台生成的任务 ID 作为关联凭据，不使用用户 Bearer Token。当前回调接口未提供额外签名校验，生产部署前需补充回调鉴权。

### 7.7 执行中心

#### 7.7.1 执行策略

- 发起执行时创建一个执行批次，并为每条用例创建任务。
- 平台调度器持续处理等待中的批次。
- 优先选择在线、支持任务类型且负载较低的执行器。
- 单轮最多分发 20 个任务。
- 实际并发数受执行器 `max_workers` 和当前活动任务数限制。
- 大批量用例不会一次性同步提交，而是分批进入执行器。
- 执行器不可用或队列已满时任务保留在待调度状态，后续轮次继续处理。
- 调度器每秒运行一轮，“单轮最多 20 个”是当前选中执行器的单轮全局分发上限。
- 当前前端列表单次最多加载和选择 200 条；1000 条用例的单批选择入口尚需继续完善，但后端批次与分批调度模型可以承载大批量任务。
- 创建批次前若没有在线且支持类型的执行器，前端拒绝发起并提示；批次创建后执行器掉线或满载时，尚未分发的任务继续等待后续调度。
- 当前已实现基础的在线、能力和低负载选取；高级多节点均衡、自动重试与故障转移尚未实现。

#### 7.7.2 执行记录

- 支持查看批次 ID、执行类型、状态、进度、用例数、通过数、失败数、触发人和开始时间。
- 支持按批次 ID、执行类型和状态筛选。
- 支持查看批次详情和任务级结果。
- 状态包括等待、运行、通过、失败、取消等。
- 批次状态根据所有任务结果自动汇总更新。
- 支持取消执行批次。

#### 7.7.3 实时进度与日志

- 画布调试和用例执行均通过执行器执行。
- 平台可查询任务实时状态和步骤日志。
- 执行器在节点开始、成功或失败时更新进度输出。
- 前端在执行期间持续刷新，不等待整次执行结束后才返回。

### 7.8 测试报告

#### 7.8.1 全局统计

- 页面顶部展示全部执行批次的综合统计。
- 统计项包括累计批次数、累计执行用例数、通过数、失败数、失败批次数、执行中批次数和累计通过率。
- 批次量、用例量和通过率展示最近 7 天相对前 7 天的环比变化。
- 展示近 14 天按日统计的批次数、用例数和通过率趋势。
- 无数据时展示明确的零值和空状态，不保留空白卡片。

累计通过率按“累计通过用例数 ÷ 累计用例数”计算；等待、运行、取消和跳过项不计入通过数，但仍可能计入批次记录及用例总数。

#### 7.8.2 报告列表

- 报告列表保留完整表格宽度，页面整体滚动。
- 搜索区域采用紧凑布局。
- 分页器固定在列表底部，与表格形成统一容器。
- 支持刷新和进入批次报告详情。

#### 7.8.3 报告详情

- 展示批次结论、通过率、任务总数、通过数、失败数和运行元数据。
- 展示任务级状态、耗时、输出和错误信息。
- 对失败任务提供集中分析区域。

### 7.9 通知中心

- 右上角提供通知入口和未读数量。
- 支持通知列表、实时消息流、单条已读、全部已读和删除。
- 通知类型覆盖执行成功、执行失败、执行器异常和系统公告。
- 执行器连接、启动、停止和异常状态变化产生通知。
- 支持通知偏好设置，分别控制执行成功、执行失败、执行器告警和系统通知。
- 通知可携带目标类型、目标 ID 和跳转地址。

### 7.10 系统管理

#### 7.10.1 用户管理

- 支持查看用户信息、状态、角色和最近登录信息。
- 支持编辑和删除用户。

#### 7.10.2 角色管理

- 支持角色新增、编辑和删除。
- 内置管理员、测试负责人、自动化工程师和只读访客等角色。

#### 7.10.3 配置与操作日志

- 支持查看系统菜单和数据字典。
- 记录项目、产品、测试资产、用例等关键新增、编辑和删除操作。
- 支持查看操作人、动作、目标和时间。

#### 7.10.4 外观设置

- 支持科技蓝、Codex 浅色、微信清新和 Kimi 月紫四种主题。
- 支持系统默认、微软雅黑和思源黑体界面字体。
- 支持 Consolas、Cascadia Code 和 JetBrains Mono 代码字体。
- 支持紧凑、标准和宽松三种显示密度。
- 外观设置保存在浏览器本地，修改后立即生效。
- 登录页和平台主界面共同适配主题变量。

## 8. 关键业务规则

### 8.1 执行器可用性

- 执行前必须存在在线执行器。
- 执行器必须声明支持当前任务类型。
- 调度时考虑执行器最大并发数及当前活动任务数。
- Token 必须与执行器 ID 匹配。

### 8.2 状态汇总

- 单任务结果由执行器回调平台。
- 批次进度由已完成任务数除以总任务数计算。
- 全部任务完成后：
  - 存在失败任务则批次失败；
  - 无失败任务则批次通过；
  - 被取消的批次保持取消状态。

### 8.3 请求头优先级

```text
接口自定义请求头 > 项目默认请求头
```

仅启用状态的项目默认请求头参与接口执行。

### 8.4 变量优先级

```text
用例参数化变量 > 环境级全局变量 > 项目级全局变量
```

运行时以 `${变量名}` 解析和替换。

### 8.5 删除策略

项目、产品、测试对象、测试资产和测试用例等核心业务数据采用软删除；删除后不再出现在正常列表，但保留历史记录关联能力。

## 9. 非功能需求

### 9.1 性能与容量

- 列表接口支持分页，默认每页 20 条。
- 测试用例单次导入上限为 200 条。
- 执行调度单轮最多分发 20 条任务。
- 执行器以最大工作线程数控制实际并发，以两倍工作线程数限制本地活动队列。

### 9.2 可用性

- 管理平台、平台 API 和执行器可独立启动。
- 执行器通过周期心跳自动恢复在线状态。
- 页面异步请求提供加载、错误和空状态反馈。
- 后端修改后应重新构建并重启服务，再通过 `/api/health` 验证。

### 9.3 安全

- 平台 API 使用 Bearer Token 认证。
- 执行器使用独立专属 Token 认证。
- 当前用户密码使用带固定前缀的 SHA-256 摘要存储；生产部署前应升级为带独立盐和成本参数的专用密码哈希算法。
- SQL 和 Python 节点属于高权限执行能力，生产使用时需要进一步补充权限隔离、密钥管理和沙箱策略。

### 9.4 可观测性

- 平台记录操作日志、执行日志、任务状态和执行器心跳。
- 执行器桌面端展示运行日志。
- 执行过程支持步骤级进度上报。
- 关键状态变化通过通知中心触达用户。

### 9.5 兼容性

- 管理平台面向现代桌面浏览器。
- UI 自动化当前以 Chromium/Playwright 为主要执行环境。
- 执行器支持 Windows 桌面 GUI，也可通过无界面 FastAPI 服务运行。

## 10. 技术与部署约束

| 组件 | 默认地址 | 说明 |
| --- | --- | --- |
| 管理平台 | `http://127.0.0.1:4173` | React 前端 |
| 平台 API | `http://127.0.0.1:8080` | Go Gin API |
| 执行器 | `http://127.0.0.1:8090` | Python FastAPI |
| PostgreSQL | `127.0.0.1:5432/synapse_qa` | 平台业务数据库 |

项目支持通过根目录 `start.ps1` 或 `start.sh` 启动。执行器也可独立运行或构建为 Windows EXE。

## 11. 当前限制与后续需求

以下能力尚未形成完整闭环，不属于当前已交付功能：

1. 接口自动化测试用例的独立编排、数据驱动和批量执行。
2. 接口自动化全局变量的独立管理与运行时解析。
3. 接口调试通过平台执行器代理执行，规避浏览器 CORS 限制。
4. 项目默认请求头中的变量替换和敏感值加密展示。
5. 菜单级、按钮级和数据范围级权限控制。
6. SQL、Python 自定义代码的沙箱、审批和细粒度权限。
7. 执行器多节点负载均衡策略、任务重试和故障转移策略。
8. 报告导出、分享、归档及质量门禁。
9. 通知对接邮件、企业微信、钉钉、Slack 等外部渠道。
10. 生产级密钥托管、审计留存、监控告警和容灾方案。

## 12. 验收基线

当前版本至少满足以下验收条件：

- 用户可登录平台并访问主要菜单。
- 可完成项目、产品、模块和测试对象配置。
- 可维护页面、元素、步骤、全局变量和测试用例。
- 可在画布中配置并调试元素、断言、SQL、变量、条件和 Python 节点。
- 在线执行器可通过专属 Token 连接平台并持续上报状态。
- 多条用例可按执行器并发能力分批调度执行。
- 执行过程可看到步骤进度和日志，完成后批次状态正确汇总。
- 测试报告可展示全局统计、趋势、列表及批次详情。
- 接口可按项目/产品维护，并在执行时自动合并项目默认请求头。
- 通知中心可接收执行和执行器相关通知。
- 用户可切换主题、字体和显示密度。

## 13. 术语表

| 术语 | 定义 |
| --- | --- |
| 项目 | 顶层业务或测试组织单元 |
| 产品 | 项目下的具体被测系统或端 |
| 测试对象 | 产品在某一环境中的可访问目标 |
| 页面步骤 | 可复用的 UI 操作或画布流程 |
| 执行批次 | 用户一次发起的一组用例执行 |
| 执行任务 | 批次内单条用例对应的执行单元 |
| 执行器 | 独立接收并运行任务的 Python 服务 |
| 有头模式 | 显示浏览器窗口执行 UI 自动化 |
| 无头模式 | 不显示浏览器窗口执行 UI 自动化 |
| 项目默认请求头 | 项目下接口执行时自动携带的公共 Header |
