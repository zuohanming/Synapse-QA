## 2. 产品概述

Synapse QA 是面向测试团队的自动化测试管理与执行平台，覆盖测试资产维护、可视化步骤编排、测试用例管理、接口自动化、分布式执行器管理、批量执行、实时日志、测试报告、AI 智能与通知和系统配置。

平台由三个运行端组成：

- 管理平台：React + Vite，提供测试资产、执行、报告、AI 与系统管理界面。
- 平台 API：Go + Gin + PostgreSQL（规划中引入 Redis + Asynq），负责认证、数据管理、执行调度、状态归档与通知。
- 执行器：Python + FastAPI + Playwright，负责任务接收、并发执行、进度上报与结果回调，可打包为桌面 EXE。

核心能力域：

- **界面自动化**：页面元素、页面步骤画布、测试用例（参数化/导入导出）、全局变量。
- **接口自动化**：接口管理（配置工作台/调试/版本）、项目默认请求头、接口测试用例（草稿/发布/测试运行）、接口全局变量。
- **执行中心**：执行批次/任务调度、实时日志、测试报告统计。
- **AI 智能**：模型配置、流式 Copilot、Tool Calling 自然语言操作系统功能（规划中：AI 全流程自动化）。
- **数据工厂**：内置测试数据生成器。
- **测试配置与系统管理**：项目/产品/模块/测试对象/执行器，用户/角色/权限/参数/审计/外观。

## 3. 产品目标

- 集中管理界面自动化和接口自动化测试资产。
- 使用画布降低复杂 UI 自动化步骤的编排与调试成本。
- 将平台管理与实际任务执行解耦，支持独立执行器横向扩展。
- 支持少量用例即时执行和大量用例分批调度。
- 实时呈现执行步骤、日志、状态和最终报告。
- 通过项目、产品、模块、环境和全局变量建立可复用的测试上下文。
- 以 AI 自然语言驱动测试全流程，逐步实现"一句话提交、全自主闭环"。

## 6. 核心业务对象

```text
项目
└── 产品
    ├── 产品模块
    ├── 测试对象/环境
    ├── 页面与页面元素
    ├── 页面步骤/流程
    ├── 测试用例与参数化数据
    └── 接口定义

测试用例
└── 执行批次
    └── 执行任务
        ├── 实时日志
        └── 执行结果/报告
```

## 7. 关键业务规则

### 7.1 执行器可用性

- 执行前必须存在在线执行器，且执行器必须声明支持当前任务类型。
- 调度时考虑执行器最大并发数及当前活动任务数。
- 执行器 Token 必须与执行器 ID 匹配（专属 Token 优先，回落共享 Token）。

### 7.2 状态汇总

- 单任务结果由执行器回调平台；批次进度由已完成任务数除以总任务数计算。
- 全部任务完成后：存在失败任务则批次失败；无失败任务则批次通过；被取消的批次保持取消状态。

### 7.3 请求头优先级

```text
接口自定义请求头 > 项目默认请求头
```

仅启用状态的项目默认请求头参与接口执行。

### 7.4 变量优先级

```text
用例参数化变量 > 环境级全局变量 > 项目级全局变量（界面自动化）
步骤临时变量 > 提取变量 > 数据集 > 用例变量 > 接口变量 > 产品变量 > 项目变量 > 系统变量（接口自动化）
```

运行时以 `${变量名}` 解析和替换。

### 7.5 删除策略

项目、产品、测试对象、测试资产和测试用例等核心业务数据采用软删除；删除后不再出现在正常列表，但保留历史记录关联能力。

### 7.6 AI 产出安全边界

- AI 产出的用例与资产默认进入草稿区，经用户确认后转正式并执行。
- AI 输入输出需脱敏、审计；高危操作不得自动执行。

## 8. 非功能需求

### 8.1 性能与容量

- 列表接口支持分页，默认每页 20 条。
- 测试用例单次导入上限 200 条。
- 执行调度单轮最多分发 20 条任务。
- 执行器以最大工作线程数控制实际并发，以两倍工作线程数限制本地活动队列。

### 8.2 可用性

- 管理平台、平台 API 和执行器可独立启动。
- 执行器通过周期心跳自动恢复在线状态。
- 页面异步请求提供加载、错误和空状态反馈。

### 8.3 安全

- 平台 API 使用 Bearer Token 认证；执行器使用独立专属/共享 Token。
- 当前用户密码使用带固定前缀的 SHA-256 摘要存储；生产部署前应升级为带独立盐和成本参数的专用密码哈希算法。
- SQL 和 Python 节点属于高权限执行能力，生产使用时需补充权限隔离、密钥管理和沙箱策略。
- 执行器回调以任务 ID 作为一次性凭据，生产部署前需补充回调鉴权。

### 8.4 可观测性

- 平台记录操作日志、执行日志、任务状态和执行器心跳。
- 执行过程支持步骤级进度上报；关键状态变化通过通知中心触达用户。

### 8.5 兼容性

- 管理平台面向现代桌面浏览器。
- UI 自动化当前以 Chromium/Playwright 为主要执行环境。
- 执行器支持 Windows 桌面 GUI，也可通过无界面 FastAPI 服务运行。

## 10. 当前限制与后续需求

以下能力尚未形成完整闭环，不属于当前已交付功能：

1. 画布工作台的前端连线、保存与调试链路（后端 flow JSON 校验已具备）。
2. 界面自动化全局变量前端 CRUD 入口（后端接口已具备）。
3. 测试配置 / 测试对象前端操作入口（仅只读列表）。
4. 接口调试通过平台执行器代理执行，规避浏览器 CORS 限制。
5. 项目默认请求头中的变量替换和敏感值加密展示。
6. 数据范围级权限控制的完整落地。
7. SQL、Python 自定义代码的沙箱、审批和细粒度权限。
8. 执行器多节点负载均衡策略、任务重试和故障转移策略。
9. 报告导出分享、归档及质量门禁。
10. 通知对接邮件、企业微信、钉钉、Slack 等外部渠道。
11. 生产级密钥托管、审计留存、监控告警和容灾方案。
12. AI 智能断言、用例生成、失败分析三个占位能力。
13. AI 自然语言全流程自动化（方案已设计，待实施）。

## 11. 验收基线

当前版本至少满足以下验收条件：

- 用户可登录平台并访问主要菜单。
- 可完成项目、产品、模块和测试对象配置。
- 可维护页面、元素、步骤、全局变量和测试用例。
- 可在画布中配置并调试元素、断言、SQL、变量、条件和 Python 节点。
- 在线执行器可通过专属 Token 连接平台并持续上报状态。
- 多条用例可按执行器并发能力分批调度执行。
- 执行过程可看到步骤进度和日志，完成后批次状态正确汇总。
- 测试报告可展示全局统计、趋势、列表及批次详情。
- 接口可按项目/产品维护，并在执行时自动合并项目默认请求头。
- 通知中心可接收执行和执行器相关通知。
- 用户可切换主题、字体和显示密度。
- AI 助手可流式对话并可通过 Tool Calling 操作系统功能。
