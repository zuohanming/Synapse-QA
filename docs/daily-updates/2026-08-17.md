## 修复执行器连接异常后无法自愈的问题

- 变更内容：执行器进程虽存活、`/health` 正常，但心跳循环因 Token 鉴权失败（401）触发 `stop_event` 后永久停止，之后即便 Token 被修正也无法自愈，后端据此判定执行器离线/连接异常。修改 `executor/app/services/heartbeat_client.py` 的 `authenticate()`：连接成功后先将验证通过的 Token 写回内存 `settings.executor_shared_token`，再调用 `start()` 重启心跳循环——`start()` 会清除停止标志并在循环已停止时重新拉起 `_loop`，循环仍在运行时自动跳过重复启动。这样 GUI 登录成功（或 Token 失效后重新登录）即可自动恢复心跳，无需手动重启执行器进程。
- 影响范围：`executor/app/services/heartbeat_client.py`（`authenticate()` 成功分支）、`executor/tests/test_heartbeat_client.py`（新增成功场景测试）。
- 验证结果：`pytest tests/test_heartbeat_client.py` 6 项通过（含新增的 `test_authenticate_success_updates_token_and_restarts_heartbeat`）；执行器全量 `pytest` 为 102 passed、59 skipped、1 failed，唯一失败 `test_fastapi_lifecycle_starts_one_capture_poller_and_health_is_non_sensitive` 因环境缺少 `httpx` 模块（`No module named 'httpx'`）而失败，为预先存在的环境问题、与本次改动无关；重启执行器加载新代码后心跳恢复，数据库 `executors.status=online` 且 `last_heartbeat_at` 每 10 秒持续更新。

## 修复打包版执行器调试页面步骤报「playwright install」

- 变更内容：桌面打包版执行器（PyInstaller 生成的 `synapse-executor.exe`）在「调试页面步骤」启动浏览器时，报 `Looks like Playwright was just installed or updated. Please run playwright install`。根因是 Playwright 在 frozen（PyInstaller）环境下会把 `PLAYWRIGHT_BROWSERS_PATH` 默认置为 `"0"`，从而到驱动目录下的 `.local-browsers` 查找浏览器，而浏览器实际安装在用户级 `ms-playwright` 缓存（`%LOCALAPPDATA%\ms-playwright`）中。修复分两层：① 在 `executor/app/core/config.py` 顶部新增 `_ensure_playwright_browsers_path()`，frozen 且未显式指定路径时自动把 `PLAYWRIGHT_BROWSERS_PATH` 指向用户级 `ms-playwright` 缓存，使未来重新打包的 exe 自包含；② 同时写入用户环境变量 `PLAYWRIGHT_BROWSERS_PATH` 并重启当前 exe，让已打包的 exe 立即生效。
- 影响范围：`executor/app/core/config.py`（新增 frozen 下的浏览器路径修正）；运行环境新增用户环境变量 `PLAYWRIGHT_BROWSERS_PATH`（`C:\Users\Administrator\AppData\Local\ms-playwright`）。
- 验证结果：用 venv 复现确认 `PLAYWRIGHT_BROWSERS_PATH=0` 时 `chromium.launch()` 报 `Executable doesn't exist ... Looks like Playwright was just installed or updated`（与用户所见一致），改为指向 `ms-playwright` 后 `launch` 成功；`config.py` 非 frozen 时不设置该变量、frozen 时正确设为 `ms-playwright` 路径；`pytest tests/test_heartbeat_client.py` 6 项通过；重启 `synapse-executor.exe` 后窗口正常启动。
