## 修复：列表元素定位器无法满足"唯一且评分 ≥ 40"

- 变更内容：修复页面元素采集（element capture）中列表行内"编辑/详情/删除"等操作元素无法生成"唯一且评分 ≥ 40"定位器的问题：
  1. 浏览器侧 `rowScopedXPath`（`element_picker.py` 的 `PICKER_SCRIPT` 与 `_DOM_EXTRACT_SCRIPT` 两处注入脚本）统一健壮化：新增 `rowLike` 行识别（覆盖原生 tr/li、role=row/listitem、Element UI/AntD/自研表格行类名），父级遍历跳过 TD/TH 单元格避免误判；anchor 选择跳过含交互控件的操作列、优先取唯一文本；支持非 `<button>/<a>` 的操作元素（span/div 绑事件）。固定操作列克隆行缺少业务锚点，或锚点 XPath 不包含被点击 DOM 时，回退为当前被点击元素对应的全局同名操作索引 XPath，而非错误的整页行索引。
  2. Python 端 `locator_generator.py`：扩展 `_ROW_CONTEXT_XPATH` 支持 li/role=listitem/非按钮标签；`row-index` 定位策略（基础分 55，免深度惩罚，语义级排序位于 stable-xpath 之后）同时识别行索引、精确动作索引与全局同名操作索引；`_match_count` 补充 row-index 到 xpath 的计数映射。
- 影响范围：执行器 `executor/app/services/element_picker.py`、`locator_generator.py`；前端采集审核门槛（unique && score>=40）与后端候选入库逻辑不变，仅让列表元素生成结果可达到该门槛。
- 验证结果：`pytest tests/test_locator_generator.py` 55 项全通过（覆盖 li 行、自定义表格行 span 操作、role=listitem、行索引、精确动作索引与全局同名操作索引）；完整执行器测试 95 passed / 59 skipped（skipped 为缺 pytest-asyncio/httpx 的环境依赖问题，非本次回归）；两处注入脚本 JS 语法经 node --check 校验通过。已重启执行器并在真实 Chromium 验证：固定操作列无业务锚点时，“编辑”生成 `(//button[normalize-space(.)='编辑'])[4]`，“详情”生成 `(//span[normalize-space(.)='详情'])[4]`，两者均为 `matchCount=1`、`score=55`。
