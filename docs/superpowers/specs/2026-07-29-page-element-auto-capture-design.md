# 页面元素自动采集设计规格

## 1. 目标

在“界面自动化 / 页面元素配置”中增加基于执行器真实浏览器的元素拾取能力。用户从指定页面对象启动有头 Chromium，会话中可在“拾取模式”和“操作模式”之间切换；拾取结果先进入候选审核区，经过质量校验、重复冲突处理和批量预检后，才写入正式页面元素库。

本期不替代现有手工新增入口，也不做全 DOM 自动扫描或完整用例录制。

## 2. 入口与交互

- “页面元素配置”保留“新增元素”，并列增加“自动采集”。
- 启动弹窗固定当前页面对象，要求选择在线且支持 UI 的执行器、输入目标 URL、选择 Chrome 或 Edge 通道。
- 同一执行器最多存在一个采集会话；会话期间执行器显示“正在采集”。
- 浏览器内悬浮采集工具条，支持：
  - 拾取模式：悬停高亮，单击采集但不触发原页面动作。
  - 操作模式：正常登录、导航、展开菜单和触发动态内容。
  - `Alt` 临时切换模式，`Esc` 取消高亮。
  - 显示候选数量、暂停和结束入口。
- 平台右侧使用候选审核抽屉实时接收元素；离开页面且存在未处理候选时必须确认。

## 3. 会话模型

一次会话绑定：

- 一个页面对象；
- 一个执行器；
- 一个浏览器上下文及标签页；
- 一个创建用户；
- 一个 30 分钟无操作失效的一次性令牌。

会话状态为 `starting`、`active`、`interrupted`、`completed`、`expired`、`failed`。执行器心跳中断时进入 `interrupted`，只允许原执行器在 60 秒内恢复；超时后结束浏览器上下文，但平台已接收的候选项保留至原会话过期时间。候选数据、局部缩略图和一次性令牌到期后清理。

平台不保存账号、密码、Cookie、Local Storage 或用户输入值。页面跳转允许继续采集，跨域时明确显示当前 URL 变化。

## 4. 浏览器与 DOM 边界

第一期仅支持有头 Chromium，Chrome 和 Edge 作为通道选项。支持：

- 普通 DOM；
- 动态加载元素；
- 同源 iframe；
- `open` Shadow DOM。

明确不支持跨域 iframe、`closed` Shadow DOM、Canvas 内部对象、浏览器原生弹窗及系统窗口。不支持区域必须在浏览器遮罩中说明原因。

默认允许采集常用交互元素、表格、列表、菜单、标签页、图片、文本块及有明确可访问语义的容器。“高级拾取”开启后可选择任意可见普通 DOM。隐藏、零尺寸、被遮挡且无法命中的元素默认拒绝。

## 5. 定位器生成与命名

每个候选最多生成三组已在当前页面验证的定位器，优先级为：

1. `data-testid`、稳定 `data-*`、唯一静态 `id`；
2. `role + accessible name`、关联 `label`；
3. 稳定 CSS；
4. 唯一且稳定的可见文本；
5. XPath 兜底。

过滤动态 ID、随机 class、超长 DOM 层级和任何包含敏感输入值的表达式。记录每个定位器的匹配数量、质量评分和拒绝原因。无可靠定位器的候选标记“需人工完善”，不可保存。

名称依次取关联 `label`、可访问名称、按钮或链接文本、`placeholder`、控件类型与相邻文本。无语义时命名为“未命名元素”，必须人工修改。名称在同一页面内唯一，默认追加业务类型或序号解决重名。

## 6. 候选、截图与容量

- 候选项包括名称、标签类型、可访问名称、最多三组定位器、唯一性、质量评分、元素指纹、当前 URL、重复状态和临时局部缩略图。
- 局部缩略图只包含元素及少量周边；敏感输入区域自动遮罩。
- 截图不进入正式元素资产，会话结束或到期后删除。
- 单会话最多保留 500 个候选，达到 400 个时告警，达到 500 个时暂停新增拾取。
- 候选列表采用虚拟滚动；单次勾选保存最多 200 个。

## 7. 重复检测与冲突

以“页面对象 + 元素指纹”识别重复。指纹综合稳定属性、可访问语义和 DOM 特征，不直接等同于定位器字符串。

冲突默认跳过，用户必须选择：

- 更新已有元素；
- 保留已有元素并忽略候选；
- 另存为新元素。

系统不得静默覆盖正式资产。

## 8. 入库、版本与事务

保存前执行全量预检：

- 页面归属合法；
- 名称唯一且非“未命名元素”；
- 至少存在一组可靠且唯一的定位器；
- 重复冲突已处理；
- 候选数量不超过 200；
- 会话、用户与权限有效。

所有勾选候选在单个数据库事务中完成新增、更新、版本记录和操作审计。任一项失败则整批回滚。

页面元素增加非敏感元数据：元素指纹、采集来源、采集 URL、标签类型、可访问名称、质量评分、采集人、采集时间、最近验证时间和验证结果。

新增元素生成 V1。更新已有元素生成新版本，历史保存名称、定位器、评分、修改人、时间和来源；支持差异查看与回滚。软删除不删除版本记录。

## 9. 权限

- `ui.element.read`：查看元素、候选和版本。
- `ui.element.capture`：启动、操作、恢复和结束采集会话。
- `ui.element.manage`：正式入库、更新已有元素和版本回滚。
- 超级管理员默认拥有全部权限。
- 有采集权限但无管理权限的用户可提交候选供有管理权限的用户审核。
- 只读用户不能启动采集。

所有会话操作、批量入库、冲突更新和版本回滚写入操作日志。

## 10. 组件边界与数据流

### 平台后端

- `ElementCaptureService` 管理会话状态机、权限、容量、断连恢复和过期清理。
- `ElementCandidateService` 负责候选校验、重复检测和事务入库。
- `PageElementVersionService` 负责版本快照、差异和回滚。
- Repository 仅负责会话、候选、元素元数据和版本的数据库读写。
- Controller 暴露平台 UI API 和执行器回调 API。

### 执行器

- `CaptureSessionManager` 创建及关闭独立有头浏览器上下文。
- `ElementPicker` 注入工具条、处理双模式、DOM/iframe/Shadow DOM 命中与高亮。
- `LocatorGenerator` 生成候选定位器、验证唯一性并计算评分。
- 执行器通过现有鉴权通道领取采集任务和回传候选，不直连平台数据库。

### 前端

- 启动弹窗负责执行器、URL 和浏览器通道选择。
- 会话状态条展示连接、倒计时、模式、当前 URL 和执行器。
- 候选审核抽屉负责实时列表、编辑、冲突决策、筛选及批量保存。
- 元素详情增加采集元数据和版本记录。

数据流：

1. 平台创建会话与一次性令牌；
2. 执行器领取会话并打开浏览器；
3. 浏览器拾取脚本生成原始 DOM 特征；
4. 执行器完成定位器生成、唯一性验证和局部截图；
5. 平台接收、脱敏、去重并推送候选；
6. 用户审核并提交批量保存；
7. 后端全量预检后事务入库并生成版本。

## 11. 错误处理

- 无在线执行器、执行器忙碌或不支持 UI：启动前阻止并说明原因。
- 浏览器启动失败：会话进入 `failed`，释放执行器占用。
- 执行器断连：进入 60 秒恢复窗口；超时结束浏览器会话但保留候选。
- 不支持的 DOM 区域：浏览器内即时提示，不产生候选。
- 候选质量不足：保留供人工完善，不允许直接保存。
- 入库预检失败：不写数据库，逐项返回字段级问题。
- 事务失败：整批回滚，候选仍保留并允许重试。
- 令牌失效或越权：执行器终止采集，平台记录安全审计。

## 12. 验收与测试

交付必须覆盖：

- 会话创建、单执行器互斥、30 分钟超时、60 秒原机恢复和结束清理；
- 一次性令牌和三类元素权限；
- 定位器优先级、动态属性过滤、唯一性及质量门禁；
- 普通 DOM、动态元素、同源 iframe、open Shadow DOM，以及不支持场景提示；
- 自动命名、元素指纹、重复冲突三种处理；
- 500 候选容量、200 批量保存限制；
- 全量预检、原子事务、版本生成与回滚；
- 临时截图遮罩与过期删除；
- 前端启动、状态、候选编辑、冲突处理和未处理离开提示；
- 真实执行器完成一次有头 Chromium 拾取、审核、入库和回滚端到端验证。

后端修改后自动重启；同步更新 PRD、接口文档、每日更新和 `CHANGELOG.md`。

## 13. 明确不在第一期

- 全 DOM 自动扫描；
- 从完整用例录制过程自动沉淀；
- Firefox 与 WebKit；
- 跨执行器迁移浏览器上下文；
- 跨域 iframe、closed Shadow DOM、Canvas 内部对象；
- 保存正式元素截图；
- 远程视频流和多人同时控制同一采集会话。
