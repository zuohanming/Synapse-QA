# 接口自动化 - 项目默认请求头

> 模块定位：为项目下的接口执行自动携带公共请求头。

## 1. 模块定位

项目默认请求头定义项目级公共 Header，接口执行时先加载项目默认请求头，再合并接口自定义请求头，同名冲突时接口自定义值优先。本模块支持请求头的维护与启用/停用。

## 2. 功能清单

- ✅ 按项目新增、编辑、删除请求头
- ✅ 启用/停用状态管理
- ✅ 按所属项目、请求头名称筛选
- ✅ 敏感信息标记（普通/敏感）
- ✅ 默认值占位提示（如 `Bearer ${token}`）
- ✅ 执行时自动合并：项目默认头 + 接口自定义头

## 3. 操作流程

1. 进入"接口自动化 / 请求头管理"。
2. 新增请求头：选择所属项目，填写请求头名称、默认值、说明与状态（含敏感信息标记）。
3. 编辑/删除请求头，或切换启用/停用。
4. 执行接口时系统按合并规则自动携带启用状态的项目默认头。

## 4. 业务规则

- 同一项目下请求头名称大小写不敏感唯一。
- 敏感头（名称含 authorization/cookie/token/secret/password/api-key 关键字）在预览与历史中脱敏展示。
- 合并优先级：接口自定义请求头 > 项目默认请求头；仅启用状态的项目默认头参与合并。
- 接口自定义空值仍视为显式覆盖；项目或产品关联失效时不加载项目默认头。
- 当前默认请求头值按明文保存；`${变量名}` 尚不会在接口调试中自动替换（边界）。

## 5. 相关接口

- `GET/POST /api/api-automation/project-headers`、`PATCH/DELETE /api/api-automation/project-headers/:id`
- 关键数据表：`api_project_headers`（project_id、name、value、description、sensitive、enabled）
