# 界面自动化 - 测试用例

> 模块定位：管理界面自动化测试用例，支持步骤关联、参数化数据集与批量执行。

## 1. 模块定位

测试用例模块（专用 `/api/test-cases`）提供界面自动化用例的全生命周期管理，包括筛选、新增、编辑、详情、删除、批量删除、导入导出，以及关联页面步骤、参数化数据集与发起执行的能力。

## 2. 功能清单

- ✅ 列表筛选：ID、用例名称、项目/产品、模块、所属页面、优先级（P0–P3）、状态（草稿/启用/停用）
- ✅ 用例新增、编辑、详情、删除、批量删除
- ✅ 用例字段：类型（UI/API/单元/混合）、优先级、状态、负责人、标签、前置条件、预期结果、描述
- ✅ 关联页面步骤（勾选列表）
- ✅ 参数化数据集管理（新增/编辑/启停/删除，variables JSON）
- ✅ 启用参数化开关（dataEnabled）
- ✅ 导入（JSON 文件，单次 ≤200 条）
- ✅ 导出（JSON，携带当前筛选条件）
- ✅ 发起执行：勾选用例 → 选择有头/无头 → 提交执行批次
- ✅ 执行前置校验：未关联步骤提示、无可用在线执行器提示

## 3. 操作流程

1. 进入"界面自动化 / 测试用例"。
2. 新增用例：填写项目/产品、模块、页面、用例名称与类型/优先级/状态等，勾选关联步骤与参数化开关，保存。
3. 编辑/详情：点击对应操作查看基本信息、关联步骤与参数化数据集。
4. 参数化：在详情面板点击"新增数据集"，填写名称与 JSON 变量，启用后供执行时数据驱动。
5. 导入/导出：点击"导入"选择 JSON 文件；点击"导出"下载当前筛选结果。
6. 执行：勾选用例后点击"执行"，选择有头/无头模式提交；系统校验执行器可用性后创建执行批次。

## 4. 业务规则

- 校验：`productId` 必填且必须存在；`name` 必填（≤120 字符）；`case_type` ∈ ui/api/unit/mixed（默认 ui）；`priority` ∈ P0–P3（默认 P2）；`status` ∈ draft/active/disabled（默认 draft）。
- 关联步骤必须是有效的页面步骤（`ui_assets` 中 asset_type=page_step 且未删除）。
- 参数化变量必须是 JSON object；同用例下数据集名称唯一。
- `data_enabled=true` 时执行要求至少一个启用数据集，否则报错。
- 导入单次 ≤200 条，逐条失败即中断并返回"第 N 条导入失败"；导出按筛选条件最多取 10000 条。
- 执行时 `url` 取用途例前置条件；无头模式为默认。
- 执行前需存在在线且支持 ui 类型的执行器，否则前端拒绝并提示。

## 5. 相关接口

- `GET/POST /api/test-cases`、`GET/PATCH/DELETE /api/test-cases/:id`、`POST /api/test-cases/import`、`GET /api/test-cases/export`
- 数据集：`GET/POST /api/test-cases/:id/datasets`、`PATCH/DELETE /api/test-cases/:id/datasets/:datasetId`
- 执行：`POST /api/executions`（run_type=ui）
- 关键数据表：`test_cases`（product_id、module_id、page_id、name、case_type、priority、status、owner、tags、preconditions、expected_result、data_enabled，unique(product_id,name)）、`test_case_steps`（case_id、step_id、sort_order）、`test_case_datasets`（case_id、name、variables jsonb、enabled，unique(case_id,name)）
