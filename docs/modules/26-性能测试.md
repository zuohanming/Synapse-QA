# 性能测试

> 模块定位：维护压测方案并承载压测执行记录与指标报告，底层压测引擎选用 Grafana k6。

## 1. 模块定位

性能测试模块（专用 `/api/perf/plans`、`/api/perf/runs`）提供压测方案的配置管理与执行记录/指标报告查看。压测方案对齐 k6 能力模型（虚拟用户数、时长、爬坡阶段、阈值断言），测试报告承载 k6 聚合指标（总请求数、平均耗时、P95、错误率、RPS）。当前阶段完成方案与报告的数据建模与界面，真实压测执行由执行器以「k6 二进制 + 子进程 + handleSummary 写 JSON」方式后续接入。

## 2. 功能清单

- ✅ 压测方案筛选：ID、方案名称、项目/产品、负载模式、优先级、状态、负责人
- ✅ 压测方案新增、编辑、详情、删除、批量删除
- ✅ 方案字段：目标接口（URL）、请求方法（GET/POST/PUT/DELETE/PATCH）、请求头、请求体、负载模式、并发数、时长、爬坡阶段、阈值断言、状态、优先级、负责人、标签、描述
- ✅ 负载配置：固定并发（vus + duration）或爬坡（stages JSON）
- ✅ 阈值断言配置（thresholds JSON，如 `{"http_req_duration":["p(95)<500"]}`）
- ✅ 触发执行（占位：创建待执行记录，等待压测执行器接入）
- ✅ 测试报告列表：ID、方案、状态、触发人、总请求数、平均耗时、P95、错误率、RPS
- ✅ 测试报告详情：关键指标卡片 + summary JSON

## 3. 操作流程

1. 进入"性能测试 / 压测方案"。
2. 新增方案：选择项目/产品，填写方案名称、目标接口 URL、请求方法与请求头/请求体；选择负载模式（固定并发或爬坡）并填写并发数/时长或爬坡阶段；填写阈值断言；保存。
3. 触发执行：在列表勾选方案点击"触发执行"，创建一条待执行记录（真实压测由执行器后续接入 k6 执行）。
4. 编辑/详情：查看基础信息、负载配置与阈值断言。
5. 进入"性能测试 / 测试报告"查看执行记录与指标详情。

## 4. 业务规则

- 校验：`name` 必填（≤120 字符）；`productId` 必填且必须存在；`method` ∈ GET/POST/PUT/DELETE/PATCH（默认 GET）；`loadMode` ∈ constant/ramping（默认 constant）；`priority` ∈ P0–P3（默认 P2）；`status` ∈ draft/active/disabled（默认 draft）。
- `loadMode=constant` 时要求 `vus > 0` 且 `duration` 非空；`loadMode=ramping` 时要求 `stages` 为合法 JSON 数组且非空。
- `headers`、`thresholds` 必须是合法 JSON 对象。
- 同一产品下方案名称唯一；方案采用软删除。
- 执行记录不软删，作为历史留存。

## 5. 相关接口

- `GET/POST /api/perf/plans`、`GET/PATCH/DELETE /api/perf/plans/:id`、`POST /api/perf/plans/:id/run`
- 执行记录：`GET /api/perf/runs`、`GET /api/perf/runs/:id`
- 关键数据表：`perf_test_plans`（product_id、name、target_url、method、headers jsonb、body、load_mode、vus、duration、stages jsonb、thresholds jsonb、status、priority、owner、tags、description，unique(product_id,name)）、`perf_test_runs`（plan_id、status、triggered_by、exit_code、total_requests、avg_duration_ms、p95_duration_ms、error_rate、rps、summary jsonb）

## 6. 压测引擎选型（K6）

- 底层压测引擎选定 Grafana k6；集成方式为「独立 k6 二进制 + 子进程 + handleSummary 写 JSON」（不使用 Go 库内嵌，因官方未提供稳定 runner API）。
- 方案字段与 k6 选项对齐：vus/duration → constant-vus，stages → ramping-vus，thresholds → 阈值断言；报告指标对齐 k6 summary metrics（http_reqs count、http_req_duration avg/p95、http_req_failed rate、rps）。
- 真实执行闭环（执行器 subprocess 调 k6、回填指标与 summary）为后续独立项。
