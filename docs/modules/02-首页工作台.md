# 首页工作台

> 模块定位：登录后的默认落地页，用于发现近期测试风险、查看执行状态并快速进入后续工作。

## 1. 模块定位

首页工作台以测试执行为核心，不再展示与当前工作无直接关系的平台资产总量。页面统一呈现当前权限和项目范围内的近期执行、失败事项、成功率和运行中任务，并提供常用业务入口。

## 2. 功能清单

- ✅ 按项目筛选，普通成员仅能看到已加入的项目
- ✅ 最近 24 小时、7 天、30 天时间范围
- ✅ 成功率、失败执行、运行中三项核心指标
- ✅ 最近 5 条 UI、API、性能测试执行
- ✅ 最近失败执行待处理事项，最多显示 3 条
- ✅ 执行详情及常用模块快捷入口
- ✅ 手动刷新和数据更新时间
- ✅ 有运行中任务时每 30 秒静默刷新
- ✅ 初始加载、无数据、局部失败和权限不足状态
- ✅ 桌面表格及窄屏执行摘要卡片

执行结果趋势和管理员平台状态属于后续阶段，P0 不显示占位区域。

## 3. 操作流程

1. 登录后进入“首页 / 项目概览”。
2. 按需选择项目和时间范围。
3. 查看待处理失败事项及三项执行指标。
4. 在“最近执行”中进入对应详情，或点击“查看全部”进入执行记录。
5. 使用快捷操作进入有权限的测试方案、执行记录、接口资产或质量报告。
6. 点击“刷新”重新获取数据；已有数据在静默刷新期间保持可见。

## 4. 状态口径

| 首页状态 | 来源状态 |
| --- | --- |
| 运行中 | pending、queued、dispatching、dispatched、running、stopping |
| 成功 | completed、success |
| 失败 | failed、execution_failed、threshold_failed、timed_out |
| 已取消 | canceled |
| 未知 | 未识别状态 |

成功率按“成功数 ÷ 当前可用来源总执行数”计算；无执行数据时显示 `—`，不会以 0% 误导使用者。

## 5. 权限和数据范围

- 首页接口要求 `menu.home.read`。
- 管理员可查看全部有效项目，并聚合 UI、API 和性能测试执行。
- 普通成员只返回 `project_members` 中已加入的项目。
- P0 中普通成员仅聚合具有不可变 `project_id` 的 API 执行；UI 和性能历史执行暂不通过可变资产关系反推项目，以避免跨项目历史数据泄露。
- 没有来源权限时返回 `forbidden`，不伪装为数量 0。
- 单个来源查询失败时返回 `partial`，其他可用数据继续展示。
- 首页不返回平台用户、角色或审计日志。

## 6. 查询与刷新规则

- 时间范围统一使用 UTC 半开区间 `[from, to)`。
- 三类来源的数量由 SQL 聚合，最近记录和失败记录使用限量查询，不将整个时间范围的数据载入应用内存。
- 默认时间范围为最近 7 天。
- 最近执行全局最多 5 条；待处理事项全局最多 3 条。
- 最近执行和待办使用 `source:id` 形式的全局唯一标识，避免不同来源 ID 冲突。

## 7. 相关接口

```http
GET /api/dashboard/overview?projectId=<optional>&range=24h|7d|30d
```

响应包含：

- `generatedAt`、`filter`
- 当前用户可访问的 `projects`
- 三类来源 `capabilities`
- `executions.state/sourceStates/counts/recent`
- `attention.state/total/items`

该接口独立于系统管理的 `/api/system/overview`，不会混入用户、角色、执行器或审计信息。
