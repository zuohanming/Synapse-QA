# 系统管理 - 角色与权限

> 模块定位：基于角色的访问控制（RBAC），维护角色及其权限矩阵。

## 1. 模块定位

角色与权限模块提供角色生命周期管理与权限矩阵配置。平台内置四类角色，权限码覆盖菜单访问与系统管理、接口自动化能力，接口级鉴权在请求时实时生效。角色权限变更后，该角色下所有用户需要重新登录。

## 2. 功能清单

- ✅ 角色列表、新增、编辑、删除
- ✅ 权限目录与权限码列表
- ✅ 权限矩阵编辑器：分组展示、全选/取消全选、复制角色
- ✅ 权限联动：勾选 `system.*` 自动附带菜单权限，取消菜单权限自动清理关联权限
- ✅ 接口级鉴权中间件（`RequirePermission`，admin 全量放行）
- ✅ 菜单列表、数据字典列表（只读）
- ⬜ 权限种子中的 `system.appearance.*`、`system.notification.manage` 无对应后端路由，属预留权限码

## 3. 操作流程

1. 进入"系统管理 / 角色与权限"。
2. 左侧选择角色，右侧编辑角色名称、说明、状态并勾选权限。
3. 新增角色：点击"+"并复制已有角色，以"副本"命名后按需调整权限。
4. 保存权限：点击"保存"，系统提示"关联用户需重新登录"。
5. admin 角色只读，显示"超级管理员始终拥有全部权限"。

## 4. 业务规则

- 内置角色：`admin` 管理员、`qa_lead` 测试负责人、`automation_engineer` 自动化工程师、`viewer` 只读访客。
- admin 角色不可修改、不可删除；删除角色前要求无关联用户。
- 新角色 code 自动生成 `role_<纳秒>`；角色状态 `active` / `disabled`。
- 权限归一化：勾选 `system.*` 自动附带 `menu.system.read`；勾选 `api.*` 自动附带 `menu.api_automation.read`；传入不存在的权限码直接报错。
- 权限变更会使该角色下所有用户 `auth_version+1`，强制重新登录。
- 权限码共 25 条，覆盖首页/界面自动化/接口自动化/数据工厂/AI/测试配置/执行中心/系统管理的菜单访问，以及系统用户、角色、设置、审计、外观和接口管理权限。
- 接口自动化模块通过 `project_members`（用户-项目-角色）实现项目级数据访问控制：admin 或项目成员可访问。

## 5. 相关接口

- 权限组：`system.role.read`、`system.role.manage`
- `GET /api/system/roles`、`GET /api/system/permissions`、`POST /api/system/roles`、`PATCH /api/system/roles/:id`、`DELETE /api/system/roles/:id`
- `GET /api/system/menus`、`GET /api/system/dictionaries`
- 关键数据表：`roles`（name、code、built_in、status）、`permissions`（code、name、description）、`role_permissions`（role_id、permission_id）、`system_menus`、`dictionaries`、`project_members`（user_id、project_id、role_id）
