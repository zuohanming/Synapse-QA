# 执行中心 - 执行调度

> 模块定位：创建、调度、监控执行批次与任务，对接执行器完成实际执行。

## 1. 模块定位

执行中心负责将用例批量组织为执行批次与执行任务，通过调度器按执行器在线状态、能力与负载分发给执行器，并汇总任务结果、更新批次状态、提供实时日志与取消能力。

## 2. 功能清单

- ✅ 执行批次创建（run_type：ui/api/unit/script/noop；有头/无头）
- ✅ 执行批次列表与筛选（批次 ID、执行类型、状态）
- ✅ 批次详情与任务级结果
- ✅ 批次取消（运行中批次可用）
- ✅ 任务日志查询
- ✅ 页面步骤调试（`POST /executions/debug`）
- ✅ 后台调度器：每秒轮询 + 唤醒信号，重启后继续处理运行中批次
- ✅ 执行中自动轮询刷新（前端 2 秒静默刷新）
- ✅ 无在线/不支持类型的执行器时前端拒绝发起并提示

## 3. 操作流程

1. 在测试用例页勾选用例并选择有头/无头发起执行，或进入"执行中心 / 执行记录"。
2. 平台创建执行批次，为每条用例创建执行任务。
3. 调度器按轮次将任务分发给在线且支持类型、负载最低的执行器。
4. 在执行记录页查看批次进度、任务结果与日志；运行中可点击"取消"。

## 4. 业务规则

- 批次状态机：pending → running → completed | failed | canceled。
- 任务状态机：queued → running → success | failed | canceled。
- 创建校验：至少选 1 个用例；执行器不可用时拒绝。
- 每轮调度：扫描运行中批次（≤100），每批次每轮最多下发 20 个任务；执行器槽位 = `maxWorkers×2 − 当前活跃任务`；槽位不足时发"队列等待"通知（每批次仅一次）。
- 执行器选取：在线且支持任务类型、当前运行任务数最少。
- 用例 status=disabled/deleted 拒绝执行。
- 批次聚合：全部任务结束后，存在失败 → failed；无通过且全取消 → canceled；否则 completed。
- 取消：终态批次不可取消；逐任务置 canceled 并向执行器发取消请求（失败不影响本地状态）。
- 回调免登录，以任务 ID 为一次性凭据；任务终态后重复回调幂等忽略。

## 5. 相关接口

- `GET/POST /api/executions`、`GET /api/executions/:id`、`POST /api/executions/:id/cancel`
- `POST /api/executions/debug`、`GET /api/executions/debug/:taskId`、`GET /api/executions/tasks/:taskId/logs`
- `POST /api/executions/tasks/:taskId/callback`（执行器回调，公开）
- 关键数据表：`execution_runs`（run_type、status、headless、triggered_by、case_ids、summary jsonb）、`execution_tasks`（run_id、task_id、executor_id、task_type、payload jsonb、status、result jsonb）、`execution_logs`
